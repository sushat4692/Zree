# Zree spec

Behaviour that must be **identical on macOS and Android**. Visual design is up to each platform.
The source of truth for the implementation is `core/` (Rust). If this document and the code disagree,
either fix the code or fix this document — do not let them drift.

## 1. Tree (the folder; `Vault` in the core)

- A tree is one folder. Everything inside it is notes and resources.
- Several trees can be remembered (most recent five on Android); switching trees only
  changes the folder the app opens.
- Scanned: `**.md` (recursive), excluding
  - directories beginning with `.` (`.git`, `.obsidian`, `.trash`)
  - `assets/` (attachments only)
- Note id = path relative to the vault, `/` separated. e.g. `ワンネス メンタリング 230502.md`
- Title = file name without the extension
- A list row shows the title, the updated and created dates and its tags — no body
  snippet (search results do carry a snippet)
- Order: newest modified first, ties broken by title ascending

## 2. File operations

| Operation | Rule |
|---|---|
| Create | without a title: `Untitled yyMMdd-HHmm` (local time) |
| Name collision | `title 2.md`, `title 3.md`, … (never overwrite) |
| Rename | same directory only; error if the target exists |
| Delete | moved to `.trash/`, not removed (`title 2.md` on collision) |
| Title sanitising | `/ \ : NUL CR LF TAB` → `-`; trim leading/trailing spaces and dots; collapse `..` to `.`; max 100 chars; empty result is an error |

**Overwrite guard**: on write, if the current mtime differs from the mtime observed when the note was
loaded, return `Conflict`. The UI reports "changed on disk" and never overwrites silently.

## 3. Tags

Inline tags only; no frontmatter. **The syntax is `@tag`.**

`#` is never a tag — it is the Markdown heading marker. Keeping them apart is why tag
completion no longer interferes with typing `# ` at the start of a line, which is what made
headings impossible to type while completions were active.

- `@` must be at the start of a line or directly after whitespace
- The body ends at whitespace, `#`, or a terminator (`、。，．！？「」『』（）【】・…—–` plus ASCII
  `, . ! ? " ' ( ) [ ] { } \` | \ / ; : * _ ~ = + ^ $ % & @`)
- **Excluded**:
  - a word glued to `@` (`sush@example.com` is not a tag)
  - anything inside fenced code blocks or inline code spans
- Migration from the old syntax: `scripts/migrate-tag-syntax.py <vault> [--dry]`
- Case is preserved. Duplicates collapse to the first occurrence.
- Filtering with several tags is AND.

## 3b. List order

`SortOrder`: updated, created (newest/oldest first) or title (A→Z / Z→A). It only applies when
the list is unfiltered; a search keeps relevance order. Both apps persist the choice.

**Both** timestamps come from Git history, not the filesystem: `created` is the first commit
that added a file, `updated` is the last commit that touched it. A clone or checkout rewrites
every mtime (that is what made every note look "updated" at the same moment), and Android has
no birth time at all, so history is the only value that survives a clone and agrees across
devices. The walk is cached in `.git/zree-times.tsv` keyed by HEAD; later opens only cover the
new commits. Notes Git has never seen keep their filesystem timestamps.

Deletion always asks for confirmation first; the note then moves to `.trash/`.

## 3c. Display settings

- macOS: font family / size / line height for the editor
- Android: editor font size, editor line height

Both persist their own settings; there is no cross-device sync for them.

## 4. Search

Japanese is written without spaces, so nothing is tokenised.

1. Normalise both query and body with **NFKC + lowercase** (width and case collapse)
2. Split the query on whitespace; **every term** must appear in the title or the body (AND)
3. Score: title match +100 (exact title +500), body match +10 + occurrences (capped at 10)
4. Snippet: 20 characters before and 40 after the first match, newlines flattened
5. An empty query returns everything, newest first

The index is held fully in memory and rebuilt lazily after mutations (fine up to tens of thousands of notes).

## 5. Markdown

Supported blocks: headings (`#`–`######`, space required after the hashes), thematic breaks
(`---`, `***`, `___` on a line of their own, rendered as a divider), bullet lists
(`-` `*` `+`, 2 spaces per indent level), ordered lists, checkboxes (`[ ]` `[x]`), blockquotes (`> `),
fenced code, images, paragraphs.
Supported inline: `**bold**`, `*italic*`, `~~strike~~`, `` `code` ``, `[text](url)`, `![alt](src)`.

The core **does not generate HTML**. It returns a token stream that each UI renders natively.

### Images

The app writes standard syntax only:

```
![](assets/2025-05-16-101726.png)
```

- Attachments live in `assets/`
- Names are `YYYY-MM-DD-HHMMSS.ext`, generated by the app on paste
- `![[file.png]]` is still understood when reading, for notes written by other editors

### Note links

Standard syntax only. `[[wikilink]]` is not supported.

Resolution rules (`resolve_link`):

1. `#heading` alone → not a link
2. `http://`, `https://`, `mailto:`, `zree:` → external
3. drop the anchor (`#…`) and query (`?…`)
4. percent-decode (`%20`, `%E3%83%A1`, …)
5. a leading `/` is relative to the vault root, anything else to the current note's directory
6. append `.md` when there is no extension
7. success only if the file exists; paths escaping the vault through `..` are rejected

Clicking a link navigates to that note (the UI intercepts it as `zree://note?id=<id>`).

## 5b. Editor assists

Decided in the core (`complete.rs`), wired by each UI.

**Return** (`list_action`), for a caret anywhere in the document:

| Line | Result |
|---|---|
| `- text` / `* text` / `+ text` | continue with the same marker and indent |
| `- [x] text` | continue with `- [ ] ` |
| `2. text` | continue with `3. ` |
| `> text` | continue with `> ` (indentation preserved) |
| empty item, no indent | remove the marker, leaving an empty line |
| empty item, indented | outdent one level (2 spaces, 1 tab or 1 space per step) |
| empty item in a nested ordered list | outdent, keeping the current number |

**Bold (and other inline markers)**: the button toggles, so pressing it twice returns to the
original text. With a selection it wraps unless the markers are already inside or just outside
the selection, in which case they are removed; with no selection it inserts a pair and puts the
caret between them, or removes the pair enclosing the caret.

**Tab / Shift-Tab on a list line** (`indent_line`): indent adds two spaces before the marker,
outdent removes one step (2 spaces / 1 tab / 1 space) and stops at the left margin. Lines that
are not list items are left alone.

Indentation is counted as width: a tab counts as one level (2 spaces) both for continuation and
for the editor, so tab-indented lists nest correctly.
| anything else | no assist |

**Completion** (`completion_context` + `suggest_tags` / `suggest_notes`):

- `@pre` at a word boundary → tag candidates (prefix match on the tag index,
  NFKC + lowercase, so width and case do not matter)
- a boundary is: start of line, whitespace (ASCII or full-width), or a list marker /
  opening punctuation (`- * + > [ ( / 、 。 「 （`). Japanese IMEs swallow the space after
  `- `, so `-@tag` must still complete
- a bare `@` offers every tag (unlike `#`, nothing else uses it)
- `[pre` → note titles, `](pre` → note paths (candidates come from the index)
- nothing is offered inside a fenced code block
- the UI replaces `caret - prefix.length .. caret`, so no byte/UTF-16 offsets cross the FFI

Full-width `＃` is also accepted by tag extraction, because Japanese IMEs produce it.

## 6. Git

- The vault itself is the repository (`.git` next to the notes)
- **Sync = commit (everything) → pull → push**, and each step is skipped when it would be a no-op
- Commit: a clean tree produces no commit
- Push: only when the branch is ahead of the remote, or when no remote branch exists yet
  (an idle vault therefore generates no network write at all)
- Pull:
  - nothing on the remote yet → treated as up to date, not an error
  - only behind (behind > 0, ahead = 0) → fast-forward
  - diverged → real merge; on conflict **stop without pushing** and return the conflicted paths
- Conflict resolution: `mine / theirs / both` (both = ours + newline + theirs). A merge commit finalises it
- Pull on launch runs only when the worktree is clean, nothing is merging, there are no conflicts and behind > 0

### Auto-sync

- Off by default? No — **on by default**, interval 5 minutes (options: 1 / 5 / 10 / 15 / off)
- Each tick: flush the editor, then run the same commit → pull → push
- Skipped entirely while a merge is in progress or conflicts are unresolved
- `commit_all` is a no-op when nothing changed, so an idle vault produces no commits
- Commit message: `zree: autosync MM-DD HH:mm`
- After 3 consecutive failures the loop stops and the error is shown once (so a missing PAT or
  being offline cannot spam)
- On quit: one final flush + sync, message suffix `(quit)`
- Auth: HTTPS + PAT only (macOS Keychain). The ssh transport is not compiled in yet.

## 7. Errors

User-facing strings are Japanese. Nothing is swallowed: save and sync failures are always surfaced.
`Conflict` means "a human must decide" — it is never auto-resolved.
