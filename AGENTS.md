# AGENTS.md — Zree

## Name

**Zree** — *Zero-friction Markdown tree* (*Zero* + *Tree*)

> A lightweight, Markdown-first note-taking app designed to stay out of your way.

The four pillars. README / UI copy / icon should use this vocabulary:

- **Zero friction** — launches instantly. No bloated UI, no manual folder management.
- **Markdown at its core** — pure, portable plain text.
- **Git-synced Tree** — built on Git's tree structure; versioned and synced across devices.
- **Self-organizing** — focus on writing; automatic tagging weaves your thoughts into a connected tree (future).

How notes connect: **tags are the primary mechanism, standard Markdown links are secondary**.
`[[wikilink]]` is not adopted (the `![[ ]]` image form is also being retired).

## Ground truth (measurements from the original vault)

The design is sized against this real data:

- 365 notes / 443 KB / 33 lines on average / 103 notes under 10 lines
- 0 folders, 0 frontmatter, 0 dataview/mermaid/callout/tables/math, 0 note-to-note links
- Actually used: headings, bullet lists, strikethrough, checkboxes, inline tags, images, Git sync
- 99 distinct tags (`#お客様打合せ` ×35, `#ワンネス` ×16, `#マネジメント` ×15, `#1on1` ×13)

## Decisions

| Topic | Decision |
|---|---|
| Platforms | macOS + Android (iOS out of scope) |
| UI | Fully native, no WebView/JS. SwiftUI + Compose |
| Logic | Shared Rust core via uniffi |
| Editor | NSTextView / BasicTextField — use the OS text system so IME is native |
| Storage | Flat `.md` files in a folder. UI calls that folder a **tree** (`Vault` inside the Rust core); no sub-folders, no naming convention |
| Search | NFKC + lowercase + substring match (Japanese has no word separators) |
| Tags | Inline tags, filter UI, automatic tagging later. **The primary way notes connect** |
| Note links | Standard Markdown only: `[label](relative/path.md)`, clickable. Accepts percent-encoded or raw names |
| Quick capture | **Rejected** — the habit is "open the app and write" |
| Templates | Deferred |
| Images | Standard `![](path)` written by the app, attachments under `assets/YYYY-MM-DD-HHMMSS.ext`; `![[file]]` is still read for compatibility |
| Distribution | macOS: ad-hoc signed `.app` / Android: sideloaded APK |
| Visual identity | Icon Composer bundle is the single source of truth; UI palettes (SwiftUI + Compose) are sampled from it |

## Explicitly out of scope

Frontmatter editing, link graph / backlinks (for now), plugin system, tables, math, Mermaid, callouts, Git LFS, folder tree UI, global hotkeys, share sheets.

## Ground rules

**Do not fight the phone for the foreground.** `adb shell input` is fine for verifying Zree, but
the device is in daily use and every injected event lands in whatever app is in front:

- check `dumpsys window | grep mCurrentFocus` first; if it is not Zree or the launcher, stop and ask
- never send `KEYCODE_HOME`, `KEYCODE_WAKEUP` or `KEYCODE_BACK` to escape — back leaves Zree and
  home/wakeup hit whatever the owner is doing
- prefer reading state Zree wrote (vault files, logcat) over screen scraping

## Verifying the macOS window without a screen recording

`ZREE_SNAPSHOT=/tmp/win.png build/Zree.app/Contents/MacOS/Zree` renders the window's content
view to a PNG two seconds after launch, so layout changes can be inspected by reading the
file. Note: `cacheDisplay` does not reproduce the sidebar's material, so colours/contrast in
the snapshot are not trustworthy — geometry is.

## Editor rendering (macOS)

The editor renders Markdown in place: headings larger and bold, list/quote markers muted,
inline bold/italic/strike/code styled, `---` drawn as a rule by a custom NSLayoutManager.
Markers are never hidden and only attributes change (undo/IME/caret unaffected).

Styling is verified headlessly: `swift test --package-path macos` builds a real
NSTextStorage/ZreeLayoutManager/NSTextView and asserts fonts, colours, the rule attribute
and typing attributes (5 tests in `macos/Tests/ZreeEditorTests`). Keep them green — they
catch the class of bug where attributes are silently ignored (e.g. `isRichText = false`).

Parsing is done once per document, then only when it can change the result:

- typing does **not** re-parse; `typingAttributes` follow the line's style, so characters
  appear at the size they will keep (no "types small, snaps big" effect)
- the edited line is re-classified only when its block kind changes (`# ` typed, list
  marker added, fence opened) — a single-line parse in the core
- a line is restyled when the caret leaves it, which is when inline styling appears
- a fence line falls back to a full restyle, since it reclassifies the lines below
